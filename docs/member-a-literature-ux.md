# 成员 A：文献管理交互设计与数据生命周期（本轮交付）

对应阶段任务「文献管理交互设计（P0）」「数据生命周期完善（P1）」。A 提供方案与数据行为约定，页面合入由 B 统一把关；本轮未修改前端代码。

## 1 文献管理现状（B 已交付）

`PapersPage` 已具备：标题搜索（前端过滤）、状态筛选、年份范围（服务端 `year_from/year_to`）、标题/年份排序、每页 50 条分页、详情、阅读跳转（研究页联动）、负责人移出（确认文案明确"不再参与检索、历史报告保留快照"）。导入走上传抽屉 + 任务恢复机制。以下建议在此基础上增量设计。

## 2 改进方案

### 2.1 列表

| 项 | 建议 | 数据侧依据 |
| --- | --- | --- |
| 服务端分页 | 文献超过约 200 篇后，`papers` API 增加 `offset/limit`（AB-1 兼容扩展，默认全量不变）；前端切换为服务端分页 | 现有 `papers(ctx, year_from, year_to)` 一次返回全量；性能基线显示点查路径无压力，深分页才是瓶颈，文献列表页浅分页即可 |
| 状态汇总 chips | 列表顶部显示 待处理/处理中/可检索/失败 计数，点击即筛选 | 来自概览 `overview` 意图（见[概览统计](member-a-overview-stats.md)），不在前端数数组 |
| 排序 | 年份相同时保持标题次序（现实现已如此）；新增"导入时间"排序需 API 返回 `created_at`（Paper schema 扩展，需与 B 对齐） | `project_papers.created_at` 已存在 |
| 失败行内重试 | 失败论文行内提供"重试处理"，进入现有任务重试链路 | `retry_task` + 幂等键；前端已有任务恢复通道 |

### 2.2 筛选

- 组合筛选（状态 × 年份 × 关键词）保持现有行为：年份变化走服务端，标题/状态本地过滤。建议统一为全部服务端过滤的时机与分页相同。
- 空结果区已有"清空筛选"入口，保留。
- 不建议做"保存的筛选视图"：单项目文献量级不需要，避免引入持久化配置面。

### 2.3 详情

现有详情为轻量抽屉。建议补齐（全部为现有 API，无需新接口）：

1. 处理信息：状态、导入时间、摘要（digest 前 8 位用于对账说明）。
2. 片段预览：`sources(paper_id)` 的页码 + 摘录前两行，"查看全部"跳研究页定位。
3. 证据情况：`evidence(paper_id)` 是否有结果、最近提取时间；无结果且状态可检索时给"提取证据"入口。
4. 任务历史：该论文的最近一次任务状态与错误信息（`tasks` 已随上传/恢复流程可见；详情中静态展示最近错误即可，失败样例的 `AI_UNAVAILABLE` 文案已可读）。

### 2.4 批量操作

| 操作 | 方案 | 服务端行为 |
| --- | --- | --- |
| 批量移出 | 表格加选择列（仅负责人可见）；确认框列出 N 篇与"保留报告快照"提示；逐篇调用现有 DELETE（`confirm_source_impact=true`） | 每篇独立事务、独立审计；部分失败时前端逐行标错并保留成功项，不做整批回滚的假象 |
| 批量重试失败 | 仅对 failed 行可用；逐篇 `retry_task` | 同上；幂等键防重复提交 |
| 批量导出/删除元数据 | 本轮不做：无对应 API，且删除论文原文件对账未完成（见下） | — |

明确不建议：伪批量（前端并发无上限的同时点击）。实现时限制并发 2–3 并显示总体进度；全部调用都带既有幂等键机制，刷新后可核对。

## 3 数据生命周期行为（P1，A 侧权威说明）

### 3.1 移出论文（remove_paper）

- 软移除：写 `project_papers.removed_at`，行保留；列表、检索、概览统计立即不再包含（部分索引 `live_project_papers WHERE removed_at IS NULL` 保证路径最短）。
- **报告引用快照保留**：`report_version_sources` 是保存时的快照副本，移出后旧版本报告仍可完整读取当时的引用（`versions` 不再联 project_papers）。
- 片段（chunks）保留在库但不再可检索/不计入概览统计；任务与结果记录保留作为历史审计依据。
- 摘要（digest）仍占用项目内唯一性：同文件重新导入返回 `DUPLICATE_PAPER`。这是有意行为（防止绕过移出语义重复导入）；如需"移出后允许再导入"，需团队确认新语义（恢复关联 vs 新身份），当前不实现。
- 不删除原上传文件：文件对账与补偿由 A/B 在真实存储接入时确认（`docs/development-guide.md` Phase 4B 约定，未知提交时禁止按超时删文件）。

### 3.2 任务恢复

- 领取即租约：worker `claim_job` 写 `task_attempts`，租约默认 120 秒（`PAPERPILOT_LEASE_SECONDS` 1–3600）。租约过期后可被重新领取，旧尝试标记 `expired`，每任务至多一个在途尝试（部分唯一索引保证）。
- 旧尝试不能提交：`complete_job`/`fail_job` 校验 `task_id + attempts` 与活跃租约，迟到写入被拒。
- 自动恢复上限：`recovery_failures` 达到 `PAPERPILOT_MAX_AUTOMATIC_ATTEMPTS`（默认 3）后不再自动领取，返回 `TASK_RETRY_LIMIT`，需用户明确重试。
- 前端 60 秒状态未知、"使用原请求核对"流程不变（Phase 2C 机制）。
- 提交结果未知（`DATA_COMMIT_UNKNOWN`）时不自动重试，按原幂等键对账。

### 3.3 报告与引用快照

- 保存即新版本：`report_versions` 行不可变（触发器保护），版本号 `(report_id, number)` 唯一，`base_version_id` 乐观并发控制（冲突返回 `VERSION_CONFLICT`）。
- 引用快照与正文同事务：`report_version_sources` 保存当时的 citation_id/paper_id/chunk_id/页码/摘录副本；之后即使论文被移出、片段变化，旧版本读取不受影响。
- `reports.current_version_id` 指向最新版本；读旧版本永远走版本链，不存在"覆盖"。

### 3.4 演示种子与生命周期

`seed-demo-project` 完全遵循上述行为：失败样例走 `fail_job`（论文状态 failed、审计 process.failed）、报告两版走真实版本链与快照。重复执行不产生新行（幂等键重放），因此可作为"重复初始化不产生重复记录"的验收手段直接复跑。

## 4 验证与边界

- 种子幂等/内容/概览统计验证见 `backend/tests/test_demo_seed_postgres.py` 与[概览统计文档](member-a-overview-stats.md)。
- 批量操作为设计方案，未经实现验证；实现时需补浏览器测试（隔离 Mock 环境），并受"移出/成员变更是同步操作、无服务端幂等承诺"的既有约束限制（Phase 4B 说明）。
- 本文生命周期说明以当前迁移（schema version 7）与 AB-1 为准；候选隔离特性（RLS、受限身份等）不改变上述业务语义。

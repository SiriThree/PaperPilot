# D 固定安全实验

运行 `python scripts/evaluate_security.py`。需要 Python 3.12、锁文件依赖和 Docker；工具不接收业务 DSN，只创建并销毁自己的 PostgreSQL 16 合成测试库。生成的 `results.json` 是原始逐项结果和计时样本，未达到目标时保留失败并退出非零。

固定用例在 `backend/tests/security_contracts/attack_cases.py`：SQL 注入／语法变形、跨项目资源访问、危险 SQL／非业务访问、恶意用户及论文提示各 10 项，另有三类统计的 21 个正常 AST 变体。正常通过要求与 A 的独立统计结果一致，不仅检查 HTTP 成功或 SQL 无异常。固定数据摘要保存在报告中。

## 对照配置

| 配置 | 应用网关 | 统计执行数据库身份与隔离 |
|---|---|---|
| no_gateway | 绕过授权和 SQL 策略，执行预设攻击候选 | 非管理员但故意放宽的测试身份，无项目视图过滤；每次事务回滚 |
| gateway_only | 实际 D 授权、AST、绑定及关键审计 | 同样放宽的身份，无项目视图过滤；仅执行已通过策略的计划 |
| gateway_and_database | 相同 D 网关 | 实际 PostgresQueryExecutor、每项目受限登录、只读事务、安全屏障视图和原生 ACL |

基线允许的写入仅发生在工具拥有的隔离库，逐次回滚，不接触真实文件、网络或其他服务。三组使用等价的两个项目、四篇合成论文（含移出样例）、年份及主题数据。另以绕过网关的视图越权、底表访问和写操作，单独证明数据库第二层的独立作用；这三个绕过结果不加入主攻击集分母。

攻击成功指预设、超出三类允许范围的候选被执行；语法本身无效或被已有数据库约束挡住时仍如实计为失败。提示词组假定攻击者已影响模型，注入固定恶意 SQL 输出，不是实际 LLM 的攻击成功率。C/D 原文输入回归另运行 `python scripts/verify_integration.py backend/tests/test_prompt_injection_postgres.py`。

## 性能口径

每类统计先预热 5 次，再记录 30 次；串行、热数据库、每次新建读取连接。保存每次总耗时、执行器耗时及两者差值，P95 使用 nearest-rank。网关新增耗时定义为适配器总耗时减去整个受限执行器调用耗时：包括授权、候选生成、AST、绑定、序列化检查及执行前后审计，保留其数据库 I/O；执行器中的连接、ACL 预检、SQL 和取数均被排除。总耗时同时报告，不能将该差值称作完整 HTTP 延迟或纯数据库 SQL 时间。

验收目标为完整配置攻击成功率 0、正常通过率至少 95%、三类网关新增耗时 P95 均不超过 200 ms，以及数据库直接绕过不成功。小规模合成数据的结果不外推到大库或高并发。模型生成 SQL 尚未启用，其效果必须另测。

## 页面演示与交接

先在可信隔离环境配置实际 A+D，按 `docs/member-d-startup.md` 启动；浏览器可复用 `scripts/preview_integration.py --state <新的绝对路径>` 和 `frontend/playwright.integration.config.ts`。该预览使用非管理员业务身份、独立审计与项目读取身份；AI 模型仍为本地替身，页面保持开发身份说明。

1. Alice 进入 D contract A，在查询页选择“按年份统计论文数量”，确认 allowed/executed、结果、请求编号和“固定模板降级”说明。
2. 选择“不支持的问题”，确认 rejected/not_executed，结果区无数据；按请求编号核对拒绝审计。
3. 复制项目页地址，退出后选择 Eve，再打开原地址，确认拒绝访问；自动化测试同时检查直接请求返回 404，不能仅凭按钮被隐藏认定安全。
4. Bob 作为项目成员只能研究与查询，不能管理成员、移出论文或读取完整审计；Alice 可按时间、动作、决策和用户筛选审计。
5. 故障或权限漂移在隔离夹具演示，不能用线上断库或篡改角色代替；Mock 的“模拟执行失败”只证明界面状态，不能计入真实 SQL 实验。

结果、场景和限制由 A/B/C/D 按各自接口复核；本文不冒充其他成员的人工签字或现场演示记录。

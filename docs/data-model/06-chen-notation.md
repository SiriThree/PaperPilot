# Chen 式 E-R 图图例与联系基数

## 图形含义

| 图形 | 含义 |
| --- | --- |
| 矩形 | 实体或关系模式阶段的联系实体，中文名下附英文标识 |
| 椭圆 | 实体属性，中文名下附字段名；下划线表示主键分量 |
| 菱形 | 两实体之间的联系，不代表新增一张表 |
| 连线 1 / N | 最大联系基数；左 1 右 N 为一对多，反向为多对一 |
| 属性字段名后的 ? | 最终模型中允许 SQL NULL；概念分图仅表达业务属性，不冻结 NULL 规则 |

例如：项目与论文导入为 1:N，即一个项目可有多次导入，而一次导入只属于一个项目；论文元数据与项目导入为 1:1。初步合并图中的论文—作者、论文—主题保留 N:N，最终关系模式以关联实体拆为两条 1:N。

图中 1/N 只标最大数量，不声称所有联系均必须存在。任务可以尚无成功结果；最小数量以以下表格及 AB-1 为准。项目必须至少一位成员、证据结果恰好五个证据字段等额外约束，见最终模型 K01—K15。

## 修改与重新生成

绘图 JSON 为 `diagrams/chen-model.json`；`entities` 保存中英文名、字段、主键标记及可空性，`views` 保存六张图的实体和联系。修改模型时先同步数据字典与需求/冲突说明，再更新 JSON 并重新生成。

在仓库根目录执行：

```powershell
npm.cmd install --prefix .runtime/er-review --no-audit --no-fund @viz-js/viz@3.31.0
node scripts/render_chen_er.mjs
```

依赖只安装到被 Git 忽略的 `.runtime`，不进入应用依赖。六张 SVG 为静态矢量图；浏览器可放大查看。身份分图采用手工坐标布局，其余采用 Graphviz 自动布局；两者使用相同的实体/属性/联系源数据。

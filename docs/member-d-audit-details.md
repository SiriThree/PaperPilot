# D 前端：查询与操作审计详情

本轮在现有页面风格内调整信息层级：顶部确认身份和项目；左侧提交统计问题、右侧查看结果；下方追溯操作审计；离线验证报告置于最后。策略决策与执行状态分别展示，不将注册适配器或离线测试通过当作当前请求成功。

## 查看具体操作

以负责人身份进入项目的“查询与审计”，在“项目审计”中点击某条记录的“查看详情”。列表同时保留中文操作名称及原始事件代码。

| 操作 | 可查看的内容 | 筛选事件示例 |
|---|---|---|
| 统计查询 | 本次提交的问题；SQL 执行级事件另有通过 AST 后重建的参数化 SQL | `secure_query.finished` / `security.query.finished` |
| 导入论文 | 标题、实际导入的论文编号；导入完成不等于解析完成 | `paper.imported` |
| 移出论文 | 操作时的标题、论文编号 | `paper.removed` |
| 证据提取 | 请求阶段的问题、论文范围及单篇标题；完成阶段的实际论文编号 | `evidence.requested` / `evidence.completed` |
| 文献问答／报告草稿 | 提交的问题、选定论文范围；完成事件与请求分开 | `answer.requested` / `draft.requested` |
| 保存／导出报告 | 报告标题、报告编号及版本编号，不记录正文 | `report.saved` / `report.exported` |
| 添加／移除成员 | 目标用户编号；添加时同时记录显示名称 | `member.added` / `member.removed` |
| 重试任务 | 原任务编号 | `task.retry_requested` |

详情还显示事件时间、决策、执行状态、策略编号、记录耗时、用户编号和请求编号。同一请求可能产生多条业务／执行级记录，通过请求编号关联。“清空筛选”重置所有筛选条件并回到第一页。

新启动一个隔离 Demo 后，依次执行：按年份统计 → 审计筛选 `security.query.finished` → 查看详情；应能看到原问题、带项目占位参数及 `LIMIT 100` 的 SQL。再提交“不支持的问题”，拒绝事件保留提交的问题，但没有已校验 SQL。执行文献导入、证据提取或移出后，在对应事件详情核对论文编号。

## 内容与权限边界

- `AuditEvent.details` 是可选结构，包含 `question`、`sql`、`resource_ids`、`resource_name`。问题最多 2000 字符、SQL 最多 4096 字符、名称最多 200 字符、资源编号最多 50 个；选择全项目材料超过 50 篇时仅保留前 50 个编号，不能把它当成完整材料清单。
- 问题和名称匹配密码、令牌、密钥、认证头或连接 URL 等敏感标记时，整段替换为隐藏提示。这是敏感标记检查，不能识别任意未标记的秘密，用户仍不应在问题或标题中输入凭据。
- SQL 仅来自允许清单匹配后重建的计划，保留项目占位参数；不记录被拒绝的模型候选、异常诊断、结果行或论文正文。存在 SQL 记录不表示执行成功。
- Vue 按文本渲染内容，不使用 `v-html`。审计详情继续由项目负责人读取，普通成员和非成员不能通过 API 获取。
- 历史记录的详情为空，不从当前标题或查询框内容推测过去的操作。旧 outbox 没有详情时继续保持旧指纹；新事件的详情纳入幂等冲突校验。

## 数据库与运行

新增正式迁移 `008_audit_details.sql`，保留既有迁移字节、旧日志和只追加触发器。它为日志增加可选 JSONB 列，并更新普通项目审计视图。运行新代码需要 schema 8；schema 7 的旧服务不能仅热更新前端后就视为完成升级。

隔离 Demo 会在新建的临时数据库应用全部迁移，启动方法见 [演示手册](member-d-demo.md)。本轮不自动升级之前归档的本机部署，也不覆盖用户已有 Demo 数据。已经安装隔离候选审计视图的环境，还需要按新的定义和显式列授权重新审核部署；不得用全表读取授权绕过预检。

原验收清单中的 985 项及三组性能结果属于此前版本的基线。新增详情后的测试以本轮报告为准；此前 P95 数字不冒称是这次改动后的重新测量。
